# 太一研发管理平台全角色走查与修复报告

**日期：** 2026年6月17日
**执行方：** Manus AI

---

## 一、 走查概述

本次走查对太一（TaiYi）研发管理平台进行了系统性、全角色的全链路审查，覆盖了从底层 API 权限到前端交互逻辑的端到端验证。走查旨在确保各角色的操作权限严格符合 PRD 定义的职责分离（Segregation of Duties）要求，同时保证前端界面的显示逻辑与后端状态机一致。

本次走查涵盖的系统角色包括：
- 产品经理 (pm)
- 技术负责人 (tech_leader)
- 开发人员 (developer)
- 测试人员 (qa)
- 系统管理员 (sys_admin)

走查发现了核心的后端越权漏洞、前端逻辑问题以及体验问题，目前已分两批次**全部修复并回归通过**。

## 二、 发现问题及修复详情

### 1. 后端接口越权流转漏洞 (FE-REQ-01)

**问题描述：**
需求通用状态变更接口 `PUT /api/v1/requirements/{id}/status`（对应 `changeStatus` 方法）存在严重的水平越权风险。该接口未对目标状态（`targetStatus`）进行角色职责校验，导致任意具有该接口访问权限的角色均可随意推进需求状态。例如，产品经理（PM）可以直接将需求状态从“测试中(TESTING)”推进到“测试通过(TESTED)”，这违背了 QA 独立负责测试验收的质量控制原则。

**修复方案：**
- **后端拦截：** 在 `RequirementController.java` 的 `changeStatus` 方法中新增 `checkStatusChangePermission` 逻辑，建立基于目标状态的严格角色门禁矩阵。
  - `TESTED` (测试通过)：仅限 `qa`。
  - `DEVELOPING` (打回开发)：仅限 `qa` 或 `tech_leader`。
  - `RELEASING` (进入发布) / `TESTING` (退回测试) / `CLOSED` (验收上线)：仅限 `pm` 或 `tech_leader`。
  - `CANCELLED` (取消需求)：仅限 `pm`。
  - `sys_admin` 具有全局兜底管理权。
- **前端同步：** 在 `RequirementDetail.tsx` 中，同步更新了状态流转按钮的可见性。基于 `RoleContext` 提供的当前用户角色，过滤 `nextStatuses`，确保无权限流转的用户在界面上根本看不到对应操作按钮。

**验证结果：** 已修复。回归测试表明，PM/开发/技术负责人尝试进行“测试通过”操作均被 403 拦截，前端详情页对应按钮已隐藏；QA 操作正常放行。

### 2. 任务指派下拉列表未过滤非开发角色 (FE-TASK-01)

**问题描述：**
在技术负责人（tech_leader）拆解需求创建开发任务时，“指派开发”下拉框（`TaskList.tsx`）加载了项目内的所有成员，包括 PM 和 QA。这可能导致任务被错误指派给非开发人员，干扰研发度量与工作台展示。

**修复方案：**
修改前端组件逻辑，在获取项目成员列表后，增加过滤条件 `m.roleInProject === 'dev'`，确保下拉列表中仅展示开发人员。

**验证结果：** 已修复。技术负责人新建任务时，指派下拉框中仅显示“王五(开发)”。

### 3. PM 工作台待处理需求负责人显示“未指派” (FE-WS-01)

**问题描述：**
在 PM 专属工作台（`ProductManagerDashboard.tsx`）的“待处理需求”卡片中，所有需求的负责人都显示为“未指派”。原因是需求列表接口（`/api/v1/requirements`）的返回结构中仅包含 `ownerId`，并未下发 `ownerName`，导致前端取值回退到默认的“未指派”。

**修复方案：**
在组件初始化时，调用 `userApi.listWithRoles()` 加载全局用户列表，并在前端构建 `ownerId -> nickname` 的映射表。渲染需求卡片时，优先通过 `ownerId` 查找映射表获取中文姓名。

**验证结果：** 已修复。PM 工作台现已正确显示需求的负责人姓名及角色（如“李四(技术负责人)”）。

### 4. 移除项目成员确认交互粗糙 (FE-PROJ-02)

**问题描述：**
在项目详情页（`ProjectDetail.tsx`）移除成员时，使用的是浏览器原生的 `window.confirm` 弹窗。这种交互方式与平台整体的 UI 风格不符，且无法提供足够的操作上下文（如被移除人的姓名）。

**修复方案：**
移除了 `window.confirm`，引入了平台标准的 `<Dialog>` 组件。在点击删除按钮时，将被操作成员对象存入状态，并在弹窗中高亮显示待移除成员的姓名，要求用户二次确认，提升了关键操作的安全感与视觉一致性。

**验证结果：** 已修复。移除成员时弹出定制化的二次确认弹窗。

## 三、 第二批次修复（2026-06-17 追加）

在首批修复完成后，基于进一步的系统性走查与业务确认，我们发现了项目级接口裸奔、前端假提交（Mock）、以及菜单闪烁等体验问题。本批次完成了彻底整改：

### 5. 项目级接口全面越权漏洞修复 (BE-PROJ-01)
- **发现**：`ProjectController` 下的所有写接口（含项目创建、更新、状态变更、框架档位调整、成员增删、迭代创建等）均无任何角色门禁，处于“裸奔”状态，任何人均可调用。
- **修复**：在后端全面引入角色校验机制（复用 `RoleChecker`）。
  - **框架档位调整**：严格限制仅 `sys_admin` 可操作。
  - **项目更新/状态变更/成员管理**：限制为 `sys_admin` 与项目归属 `pm` 可操作。
  - **迭代规划**：限制为 `sys_admin`、`pm` 与 `tech_leader` 可操作。
- **验证**：后端自动化脚本回归通过，越权拦截生效。

### 6. 成员项目角色一致性对齐 (FE-PROJ-03)
- **发现**：添加项目成员时允许手动选择“项目角色”，导致与成员的账号系统角色发生冲突。
- **修复**：
  - 前端：移除添加成员弹窗中的“项目角色”选择下拉框。
  - 后端：`addMember` 接口忽略前端传参，自动获取该用户的账号系统角色（如 `dev`、`qa`）并写入项目成员关系表。
  - 列表展示：成员列表移除原项目角色字段，改为只读展示成员的系统账号角色，保持全局一致。

### 7. 工作台按钮“假提交”与跳转优化 (FE-WS-02)
- **发现**：各角色工作台（Dashboard）顶部的快捷操作按钮多使用 `setTimeout` 进行“假提交（Mock）”并未真正落库；同时，部分操作如“新建需求”、“提交缺陷”会发生不必要的页面跳转，中断了工作台的操作连贯性。
- **修复**：
  - **全面弹窗化**：将“新建需求”、“提交缺陷”、“任务拆解”、“发起评审”等核心操作全部改造为在本页直接弹出的全功能表单窗口，实现“非必要不跳转”。
  - **真实接口闭环对接**：将原先 Mock 的弹窗（如技术债务、工时填报、提测申请、测试执行、Bug验证、变更申请）全面对接真实的后端接口。例如，拆解任务弹窗现在会真实调用 `taskApi.create` 并逐条落库；测试执行弹窗会真实拉取用例并逐条记录执行结果。
  - **移除无效入口**：开发工作台的“代码提交”因无后端接口支撑，已从界面移除，避免误导。

### 8. 界面体验细节优化 (FE-UX-01)
- **清理解释性文字**：全局移除了各类面板标题后的冗余括号说明（如将“我的待办（可直接处理）”精简为“我的待办”），使界面更加清爽专业。
- **彻底修复菜单闪烁**：
  - **现象**：用户多次反馈，刷新页面后第一次点击每个菜单，左侧导航栏都会闪烁消失一下，之后再点就不闪了。
  - **根因**：路由组件（`App.tsx`）使用了 `React.lazy` 进行页面代码的按需加载，并且将整个布局组件 `DashboardLayout` 和页面内容一起包裹在了同一个 `Suspense` 中。当首次加载某个页面的代码包时，`Suspense` 触发 fallback，导致整个布局（包含左侧菜单）被替换为 Loading 占位，从而产生菜单消失的闪烁感。
  - **修复**：重构了路由层级，将 `DashboardLayout` 提取到 `Suspense` 外层。现在懒加载触发 fallback 时，仅在右侧内容区域显示 Loading，左侧菜单栏保持常驻不闪烁。

### 9. 效能度量模块假数据治理 (FE-METRIC-01)
- **发现**：效能度量页面存在严重的「真假混合」问题。虽然“已完成任务、任务完成率、严重Bug数、需求完成率”等 KPI 卡片确为后端真实统计，但页面同时混入了大量前端写死的虚构数据：
  - “平均周期(天)”固定写死为 `3.2`；
  - “团队成员贡献度”中李四/王五/赵六/张三 的“完成任务/修复Bug/代码审查/效能分”全部为硬编码假值，且“代码审查”“效能分”后端根本不存在对应数据；
  - “迭代燃尽图”的 Day1~Day8 计划/实际曲线为写死的假曲线；
  - 顶部“当前迭代/上一迭代/近一月/近一季度”时间筛选器切换后不影响任何数据（未传递给后端），属于无效控件；
  - 概览接口将项目ID硬编码为 `1`，无法切换项目。
- **修复**：将整个页面重构为**完全由后端真实数据驱动**。
  - **真实项目选择**：用项目列表接口（兼容分页 `data.records` 结构、字段 `projectName`）渲染项目下拉，替换原无效的时间筛选器，按选中项目实时拉取数据。
  - **真实工作量**：接入此前未被使用的后端 `/metrics/workload` 接口，按人展示“总任务/已完成/预估工时/实际工时/完成率”，并通过 `users/with-roles` 映射真实姓名与角色；删除虚构的“代码审查”“效能分”。
  - **真实迭代进度**：接入 `/metrics/sprint/{id}/burndown` 真实统计（总任务/已完成/剩余），无迭代或迭代未关联任务时给出明确文案，不再绘制假曲线。
  - **指标替换**：用后端真实的“Bug修复率”替换原写死的“平均周期 3.2”。
  - **洞察文案**：效能洞察建议全部由真实指标动态生成。
- **验证**：浏览器实测，页面展示项目“太一商城重构项目”的真实数据（任务 2/2 完成、Bug 1 个已修复、王五真实工时 24h、需求完成率 0%），与数据库完全一致，所有假数据已清除。

## 四、 最终结论

经过多轮系统性走查与修复，太一研发管理平台在**权限安全性**、**业务流转闭环**以及**前端交互体验**上得到了显著提升。所有的“假提交”操作均已被真实接口替代，越权漏洞被全面封堵，各角色的工作台真正成为了高内聚、全闭环的生产力中心，影响体验的“首次点击菜单闪屏”顽疾已彻底根除，效能度量等模块的“假数据”问题也已全面治理为真实数据驱动。系统现已具备稳定投产的能力。
