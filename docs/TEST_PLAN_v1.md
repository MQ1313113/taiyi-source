# 太一研发管理平台 系统测试计划 v1.0

> 测试日期: 2026-08-20 | 被测版本: rd-platform-service 1.0.0 (当前主干) | 环境: dev (api-dev MySQL)

## 1. 测试范围与风险定级

| 风险级 | 范围 | 理由 |
|---|---|---|
| **R1 高** | 认证与账号安全、RBAC 权限矩阵、数据隔离(项目成员/私有项目) | 越权与数据泄露不可接受 |
| **R2 高** | 核心状态机(需求/任务/缺陷/发布单)与职责分离门禁 | 平台核心价值即流程强制 |
| **R3 中** | 质量门禁(AC/用例/证据/覆盖率)、档位差异、边界值 | 错放行→质量失守;错拦截→流程卡死 |
| **R4 中** | 治理机制(变更双审/仲裁/工单SLA/技术债闸门/迭代处置) | 死锁与兜底路径 |
| **R5 低** | 周报/转报/待办展示等辅助功能 | 失败可容忍,不阻断主流程 |

## 2. 测试方法

- **状态迁移法**: 对需求(9态)/任务(5态)/缺陷(8态)/发布单(5态)绘制迁移表,覆盖全部合法迁移 + 每实体≥3条非法迁移(跳态/回退/终态再迁移)
- **判定表法**: 档位(轻/标/全)×校验项(缺陷结构化/用例步骤/L2L3字段/发布卡点)组合;项目类型(团队/单人)×操作直通矩阵
- **等价类/边界值**: 字数阈值(驳回≥20/回滚≥20/冒烟≥10/复盘≥50/实际结果≥10)取 边界-1/边界/边界+1;数值阈值(会话1~168h/工时>0/步骤≥2)
- **权限矩阵法**: 5角色(admin/pm/dev/qa/项目经理)×12关键操作,断言 允许/403
- **场景法**: 防自审×5、双审死锁→仲裁、工单转化闭环等跨实体场景

## 3. 准入/准出

- 准入: 应用可启动、种子账号可登录、专用测试数据可创建
- 准出: R1/R2 用例 100% 通过;R3/R4 ≥95%;全部失败项有缺陷记录与定级
